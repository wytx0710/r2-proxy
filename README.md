Cloudflare Worker R2 静态资源代理 & 缓存服务
一个基于 Cloudflare Pages 边缘函数 实现的高性能静态资源代理服务，支持 R2 存储托管 + 源站镜像回源 + 多级缓存，一键实现静态资源全球加速、成本优化与高可用托管，零服务器、零运维，全程依托 Cloudflare 全球 CDN 节点极速分发。
核心功能
- ✅ 仅允许 GET 请求，自动拦截非 GET 请求并返回 405，拒绝非法提交与恶意请求
- ✅ Cloudflare 缓存优先机制，缓存命中直接返回内容，访问速度极致加速
- ✅ R2 存储托管优先：优先从 Cloudflare R2 对象存储读取静态资源，保护源站不暴露
- ✅ 智能镜像回源能力：R2 无对应资源时，自动从外部源站拉取文件并永久存入 R2持久化
- ✅ 自动边缘缓存写入：资源响应后异步写入 Cloudflare 边缘缓存，后续访问不再重复回源
- ✅ 标准 HTTP 缓存响应头，同时优化浏览器本地缓存与 CDN 边缘缓存双重策略
- ✅ 根路径自动映射首页：访问网站根目录 `/` 自动返回 R2 内的 `index.html`，适配静态网站建站需求
适用场景
- 静态网站、个人博客、展示站全球 CDN 加速访问
- 图片、JS、CSS、字体等各类静态资源专属 CDN 加速托管
- 减轻原站服务器压力，大幅降低源站带宽消耗与运维成本
- 高可用静态资源长期托管（R2 持久化存储 + 边缘多层缓存）

⚙️ Pages 部署固定配置
构建、部署无需复杂命令，平台必填项统一填简易指令即可，不影响任何功能：
- 构建命令：echo ok
- 部署命令：echo ok
- 构建输出目录：/
- 根目录：留空
🔗 前置准备与 R2 绑定（必做）
1. 提前创建好专属 Cloudflare R2 存储桶
2. Pages 项目后台进入：设置 → 函数 → R2 存储桶绑定
3. 环境变量名称固定填写：R2_BUCKET（代码已适配，不可改名）
4. 选择对应 R2 存储桶并保存配置，否则无法正常读取资源
🔧 快速配置与上线
1. 将代码写入根目录 _worker.js 并上传仓库
2. Cloudflare Pages 关联 GitHub 仓库并完成部署
3. 修改代码内回源地址为自己的真实源站域名：
// 替换为你的真实源站域名即可
const originUrl = "https://your-origin.com" + url.pathname;
📌 访问路径规则
- 访问 https://xxx.pages.dev/ → 自动返回 R2 中的 index.html 首页
- 访问 https://xxx.pages.dev/images/logo.png → 优先读取 R2 对应路径静态资源
🔁 完整工作流程
1. 接收用户请求 → 校验请求方法，仅放行 GET 请求
2. 优先查询 Cloudflare 边缘缓存，缓存命中直接返回资源，速度最快
3. 缓存未命中 → 优先从 R2 存储桶读取对应资源文件
4. R2 无该资源 → 自动从配置源站下载文件 → 自动存入 R2 永久保存
5. 资源读取成功后返回前端，同时异步写入边缘缓存
6. 下次相同请求直接走缓存或 R2，不再频繁回源，全程极速访问
📄 响应头缓存优化
Cache-Control: public, max-age=600, s-maxage=86400
ETag: 自动从 R2 获取
Content-Type: 自动识别资源类型
- max-age=600：浏览器本地缓存 10 分钟，重复访问无需重复请求
- s-maxage=86400：Cloudflare CDN 边缘缓存 1 天，长期加速减负
📊 状态码说明
- 200 OK：请求成功，正常返回对应静态资源
- 405 Method Not Allowed：非 GET 请求被拦截拒绝访问
- 404 Not Found：R2 和源站均无对应资源，访问失败
